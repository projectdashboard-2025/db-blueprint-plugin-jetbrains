Features

Everything your schema needs, nothing it doesn't

DB Blueprint stays out of your way. One tool window, your whole schema workflow.

🖼
Canvas editor
Drag column handles to draw FK relationships. Edit table names, types, PK / NN / UNIQUE flags inline. Minimap and zoom keep large schemas navigable.
🌿
Living schema
Capture a baseline, then edit freely on the canvas. Preview the exact ALTER statements that will bring the database up to date — before running anything.
⬇️
Import from DB
Reverse-engineer an existing database into the canvas over JDBC. Tables, columns, indexes, and foreign keys — including partial indexes — are all imported.
🛡
Pre-flight checks
Before Apply, the plugin checks for NULL values in new NOT NULL columns, duplicates before UNIQUE, and orphaned FK rows — blocking the plan with a clear message instead of a raw database error.
🔍
DDL preview
Inspect the generated CREATE / ALTER SQL at any point. Copy to clipboard, review the diff before running. Resizable window, no surprises.
📂
Save as .dbdesign
The canvas is a JSON file that lives in your project. Commit it alongside your code and open it on any machine. No external service, no account required.
Migration diff

Minimal ALTER, not DROP + CREATE

The diff engine produces the smallest set of statements needed — column renames, type changes, index updates, FK actions. A table is never dropped and recreated when an ALTER will do.

Preview migration SQL PostgreSQL
-- Step 1: New tables CREATE TABLE "audit_log" ( "id" bigserial PRIMARY KEY, "user_id" bigint NOT NULL, "action" varchar(128) NOT NULL, "created_at" timestamptz DEFAULT now() ); -- Step 2: New columns on existing tables ALTER TABLE "orders" ADD COLUMN "updated_at" timestamptz; -- Step 3: New foreign keys ALTER TABLE "audit_log" ADD CONSTRAINT "fk_audit_log_user_id" FOREIGN KEY ("user_id") REFERENCES "users"("id") ON DELETE CASCADE;
Safety

Know before you apply

Pre-flight checks run against your live data before a single statement executes. A clear message explains what is wrong and how to fix it — not a raw database error.

✅
New tables 3 tables to create — no conflicts detected.
⚠️
NOT NULL on orders.notes — 142 existing rows have NULL Set a DEFAULT or backfill before marking this column required. Apply is blocked until resolved.
✅
UNIQUE on users.email 0 duplicate values found — safe to apply.
🚫
FK audit_log.user_id → users.id — 7 orphaned rows Some user_id values have no matching parent in users. Fix the data or the relation before proceeding.

FAQ

Common questions

Do I need DataGrip or the Database plugin?
No. DB Blueprint uses its own JDBC connection and works in IntelliJ IDEA Community Edition and any other JetBrains IDE. The Database plugin is not required.
How do I connect to my database?
Open Settings → Tools → DB Blueprint, fill in host / port / database / user, point to your JDBC driver jar, and click Test connection. The plugin can auto-detect drivers already installed by your IDE, or download one from Maven Central with the Download button.
Are JDBC drivers included?
No — drivers are not bundled. Use Detect (finds drivers from any installed JetBrains product on your machine), Download (fetches from Maven Central), or point to your own .jar file.
Where are passwords stored?
In IntelliJ Password Safe — the same place your IDE stores all other credentials. Passwords are never written to the .dbdesign file or any project XML.
Is it safe to use on a production database?
The Preview migration flow — baseline → diff → pre-flight checks → Apply — is designed for production use on PostgreSQL, MySQL, MariaDB, and SQLite. MSSQL is experimental; use a staging database there. Always review the SQL in Preview before applying.
Is the plugin free?
Yes, completely free. No account, no usage limits, no paid tier.
